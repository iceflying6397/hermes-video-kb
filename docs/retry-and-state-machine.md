# 失败后继续

每条链接先进入本地队列。本地保留不代表已写入 Notion，也不保证视频内容已取得。

说“继续处理没完成的链接”，助手调用 `retry`，每次最多处理五条。查看返回的 `pending` 说明未完成任务；`items` 为空不等于全部成功。

正文在调用摘要前持久保存。`waiting_summary` 表示正文留在本机、尚未写入 Notion；恢复会复用，不要求用户重发。真实媒体和识别尚未完成时，重试可能重新下载／识别。缺少本地组件应先按说明准备，不自动改走云端。

保存已发送但结果未知时停止创建。已有候选页面／库链接，先只读核对身份、父级和完整正文；同来源别名跟随原任务，不建第二份。没有候选地址时才请用户提供链接，用 `recover --job-id 任务编号 --page-url 笔记链接` 或 `recover --page-url 库链接`。回读缺尾部、缺中段、截断或未返回正文都保持待确认。

升级保留已有绑定和状态。旧已保存笔记返回原页面，不会自动补摘要、覆盖或升级为视频转写。旧未知任务若已无本地原稿，只能明确说明全文尚未验证，保留任务，不能删状态重新建库。

平台读取失败只保留本机任务；页面可读但证据不足可以保存待复核内容，不称完整笔记。不循环绕过登录或验证码。单条失败／待摘要任务达到三次上限后，用户明确要求再试才运行 `retry --job-id 任务编号`；未知写入仍不重发。

暂停保留连接、任务与笔记；恢复后可继续队列。断开保留待办，重连同一账号／工作区。`status` 看本机历史，`check` 核验当前 Notion，`doctor` 检查模型与本地 ASR；三者不能互相替代。
